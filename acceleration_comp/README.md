# acceleration_comp — оценка скорости и ускорения вагона

Реализация методики Strauß, Hasberg, Hensel (2009): модель-обусловленное
ре-сэмплирование (warping) сигналов двух дальномеров перед взаимной
корреляцией.

## Файлы

| Файл | Назначение |
|---|---|
| `acceleration_compensation.m` | Ядро: синтез сигналов по профилю, выбор окон, оценка `(v, a, q)`, таблица и сводка качества |
| `verify_acceleration_comp.m` | Поверка математики на независимых моделях; печатает `[OK]/[FAIL]` по каждой проверке |
| `demo_acceleration_comp.m` | Прогон по профилям `wagon_12_6995`, `sine`, `step` в обоих режимах окон + графики |
| `study_window_length.m` | Перебор длины окна и перекрытия (пишет `results/window_study.*`) |
| `research_speed_measurement_hump_yard.md` | Исследование точности и применимости в реальном времени |

## Модель

Два датчика на базе `L` видят тот же профиль вагона с задержкой `tau = L/v`.
При ускорении задержка меняется вдоль окна, поэтому корреляция даёт смещение.
Метод пересэмплирует оба сигнала в постоянный пространственный шаг:

```
v = L / (lag*Ts),     a = 2*q*v / D,     D = (N-1)*Ts
```

`q = a*D/(2*vm)` в `[-1, 1]` — относительное изменение скорости по пути
(торможение до нуля: `q = +1`, трогание с нуля: `q = -1`).

## Выбор окон

Окно — временной отрезок **первого** канала; второй датчик берётся на
`[i0, i0+W-1+lagMax]`, потому что он видит ту же полосу профиля позже.

* `fixed` — окна шириной `W` с шагом `hop`, первое окно начинается с `t = 0`.
* `feature` — окна вокруг деталей (тележки, подножки, резервуар).

Окна помечаются `Region = run | ledge`; сводка качества считается по ним
отдельно. `ledge` — передняя кромка вагона, когда каналы видят разные части
профиля и корреляция заведомо слабее.

## Отбраковка

Признаки пишутся в таблицу: `Correlation`, `QContrast`, `LagPeakMargin`,
`LagSpread`, `Status`.

* по умолчанию отбраковка — `rho < minCorr` и максимум на границе поиска;
* `StrictWarpChecks = true` добавляет проверки `lagSpread` и `qContrast`.

Разделение сделано намеренно: у профиля вагона кривая `rho(q)` плоская
(изменение порядка `1e-4`), и жёсткий порог по `qContrast` исключил бы почти
все окна — оценок скорости не осталось бы вовсе.

## Запуск

```matlab
cd acceleration_comp
verify_acceleration_comp            % поверка математики
demo_acceleration_comp              % прогон по профилям и графики
study_window_length                 % перебор длин окон (долго)
```

## Настройки по умолчанию

`Ts = 10 мс`, `T = 10 с`, `L = 0.5 м`, зазор `0.4 м`, `noiseStd = 0.033 м`,
`speed0 = 4 м/с`, `accel0 = -0.5 м/с²`, `speedMin = 0.3`, `speedMax = 3.0 м/с`,
`windowMode = 'feature'`, `minCorr = 0.95`, `qLimit = 0.8`.
